# ターミナルの大きさに合わせて文字盤を自動で切り替える（設計）

日付: 2026-11-07

## 目的と背景

プレゼン中、スライドの端に小さなターミナルを置き、`clock` / `countdown` /
`stopwatch` を表示しておきたい。現在の文字盤は 9 行のアスキーアートで、
`clock` は `HH:MM:SS` で横に 70 桁ほど使うため、小さなペインには収まらない。

そこで、ターミナルの大きさに応じて、収まる中で一番大きい文字盤を
**実行中に自動で** 選ぶ。小さい文字盤として、keycap 絵文字の 1 行表示
（`1️⃣2️⃣:3️⃣4️⃣:5️⃣6️⃣`）と、テキストの 1 行表示（`12:34:56`）を同梱する。
利用者が自作した文字盤も候補に加えられるようにする。

## ゴール

- 実行中のライブ表示（`clock()`, `countdown(...)`, `stopwatch(...)`）が、
  描画のたびにターミナルの大きさを確かめ、収まる中で一番大きい文字盤を選ぶ。
- 実行中にペインの大きさを変えても、次の描画から追従する。
- `src/dials/Keycap.toml` と `src/dials/Text.toml` を同梱する。
- 利用者が複数の文字盤 TOML を候補として登録できる。
- 秒は省略しない。`clock` / `countdown` は `HH:MM:SS`、`stopwatch` は
  `MM:SS:mmm` のまま表示する。
- TOML の仕様を、1 行の文字盤と詰めた表示（区切りなし）に対応させる。

## やらないこと

- 秒を省いた `HH:MM` 表示などの、表示項目を減らすモード。
- Text 文字盤（8〜9 桁）よりさらに狭いときの切り詰め。そのときも Text 文字盤を
  そのまま出す（はみ出しは許容）。
- ターミナルの実際の絵文字幅を問い合わせて測ること（カーソル位置の問い合わせ等）。
- 色付けなどの装飾。

## やってはいけないこと（壊したら失敗）

- 既存の TOML 文字盤ファイル（`[Large]` 必須、`[Small]` 任意）が今まで通り読めること。
- 既存の preference `tomlfile`（`set_dials` で保存）が今まで通り効くこと。
- 単発でフレームを返す `clock(::Time)`, `clock(::DateTime)`, `stopwatch(::Time)` の
  戻り値が今と同じ文字列であること（既存の doctest・テストを壊さない）。
  例外: 行の幅がそろっていない文字盤では、下記の「幅をそろえる」処理により
  戻り値が変わる。これは意図した修正として受け入れる（利用者が決定）。
- countdown / stopwatch の時間計測の精度（単調時計、描画時間の差し引き）を落とさないこと。

## 決めたこと

### TOML 仕様の拡張

- 既存のキー（`zero`〜`nine`, `colon`、`[Large]` / `[Small]`）は変えない。
- 各テーブルに省略可能な `separator`（文字列）を追加する。桁と桁（コロン含む）を
  横に並べるときの間に入れる文字列で、省略時は現在と同じ空白 1 つ `" "`。
- 1 行の文字盤は、各キーに要素 1 つの配列を書けばよい（例: `one = ["1️⃣"]`）。
- 同梱する `Text.toml`: 数字は `"0"`〜`"9"`、`colon = [":"]`、`separator = ""`。
  `[Small]` も同じ内容。結果は `12:34:56`、ストップウォッチは `02:03:456`。
- 同梱する `Keycap.toml`: 数字は keycap 絵文字（`数字 + U+FE0F + U+20E3`）、
  `colon = [":"]`、`separator = ""`。`[Small]` も同じ内容。

### 表示幅の扱い

- 文字盤の幅は「各行の表示幅の最大値」とする。表示幅は `textwidth` を基本とし、
  keycap の並び（`U+FE0F U+20E3` を含む書記素）は **2 セル** として数える
  （多くのターミナルは 2 セルで描くが `textwidth` は 1 を返すため、安全側に倒す）。
- 文字盤を読み込むとき、同じ文字盤内の各行を右側の空白で埋めて幅をそろえる。
  手書き TOML の多少のずれで横に並べたときに崩れないようにするため。
- この埋めは共通の読み込み処理に入れ、単発フレームを含むすべての表示に効かせる（利用者が決定）。
- 同梱の `src/dials/ASCII2.toml` の `[Small]` `seven` は最後の行だけ幅 4（他は 5）で、
  現状 ASCII2 のストップウォッチでミリ秒に 7 が出ると行がずれる。この行を幅 5 に直す。
  ASCII と UnicodeBox は幅がそろっていることを確認済みで、戻り値は変わらない。
- `test/references/` に ASCII2 の参照テストを追加する（現在は ASCII と UnicodeBox のみ）。

### 候補の登録と順序

- 候補の並びは、「利用者が登録した文字盤（登録順）」→ 同梱 `Keycap.toml` →
  同梱 `Text.toml`。登録が 1 つもないときは、既存の `tomlfile` preference の文字盤
  （未設定なら同梱 `ASCII.toml`）を先頭にする。
- 選び方: 並びの先頭から順に見て、**フレーム全体（高さ・幅）がターミナルに収まる
  最初の候補** を使う。どれも収まらなければ最後の候補（Text）を使う。
  大きさで自動ソートはせず、登録順を優先度とみなす。
- 「収まる」の判定: フレームの行数 ≤ ターミナルの行数 − 1（最後の改行とプロンプト分）、
  かつフレームの幅 ≤ ターミナルの桁数。ターミナルの大きさは `displaysize(stdout)`。
- 登録の API: `set_dials` に複数ファイルを渡せるようにする
  （`TerminalClock.set_dials(["/abs/big.toml", "/abs/mid.toml"])`）。
  preference は新しいキー（例 `tomlfiles`、文字列の配列）に保存する。
  既存の `set_dials(::AbstractString)` は今まで通り `tomlfile` に保存し、意味も変えない。
  `clear_dials()` は両方を消す。
- 読み込みは今まで通り import 時（`const`）に行い、変更には再起動が必要。
  「動的」なのは候補の中からの選択であって、候補の登録ではない。

### ライブ表示の描画

- `clock()`, `_countdown`, `_stopwatch` は描画のたびに候補を選び直す。
- 描画のたびに **画面全体を消してカーソルを左上に移してから** 描く
  （例: `\e[H\e[2J`。利用者が決定）。行数ぶん上へ戻って消す今の方式では、
  ペインを縮めたときの折り返しで残骸が残ったり画面が流れたりするため。
  そのペインにあった REPL の過去の出力は見えなくなるが、時計専用ペインでの利用を想定し許容する。
  ライブ表示を抜けたあと（Ctrl+C や countdown 終了）は最後のフレームを残す。
- テストしやすいよう、ターミナルの大きさを得る関数を注入できるようにする
  （既存の `now_ns` / `wait` / `render` / `clear` と同じ流儀で、例えば `termsize=() -> displaysize(stdout)`）。
- 単発フレームの関数（`clock(::Time)` 等）は候補の先頭の文字盤を使う。
  つまり `tomlfiles` が登録されていればその 1 番目、なければ今まで通り
  `tomlfile` の文字盤（未設定なら ASCII）。（私の判断）文字盤を引数で渡せる
  内部用の版を用意し、ライブ表示はそれを使う。

### ドキュメントとテスト

- `docs/src/dials.md` に `separator`、1 行の文字盤、複数登録、自動切り替えを追記する。
- テストは TDD（t_wada 流）で書く。ターミナルの大きさを注入して、大・Keycap・Text が
  それぞれ選ばれること、毎回画面全体を消してから描くことを確かめる。

## 実装者に任せること

- 内部の型・関数の名前と分け方（例: 文字盤の集合を表す型、選択関数）。
- 表示幅の計算の細部（書記素の分割方法など）。上記の「keycap は 2 セル」を満たせばよい。
- `Text.toml` / `Keycap.toml` の `[Small]` の中身を変えるかどうか（同じでよい）。
- preference キー名の最終決定。
